# Astana Travel

Веб-приложение для поиска и сравнения отелей и планирования поездок. Каталог включает направления в ОАЭ, Турции, Таиланде, Египте, на Мальдивах, во Вьетнаме и на Бали.

## Запуск локально

Требуется Node.js 18.18 или новее.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Для production-сборки и локального запуска используйте:

```bash
npm run build
npm start
```

## Страницы

- `/` — каталог и рабочее пространство приложения
- `/catalog` — каталог отелей
- `/favorites` — избранное
- `/trip-finder` — подбор поездки
- `/compare` — сравнение отелей
- `/recent` — недавно просмотренные отели
- `/tinder` — подбор отелей в формате карточек
- `/ai-assistant` — помощник по поездкам
- `/account` — профиль
- `/admin/dashboard`, `/admin/bookings`, `/admin/hotels`, `/admin/customers`, `/admin/reviews` — разделы администрирования

## Данные и серверный backend

Каталог отелей остаётся демонстрационным (начальные данные из `src/data/appData.js`), но серверный режим хранит его и изменения администратора в PostgreSQL. В серверном режиме отзывы, модерация, аудит, избранное, заметки, история просмотров, сравнение и настройка темы также хранятся в базе и доступны после входа с другого устройства. В демонстрационном режиме эти данные хранятся в `localStorage` браузера.

При отсутствии `DATABASE_URL` приложение работает в демонстрационном режиме только локально. Серверный режим использует PostgreSQL для аккаунтов, SMS-подтверждения, заявок и приглашений в поездку. Приглашённый входит с подтверждённым номером и получает доступ только к участникам поездки, на которых его пригласили; владелец может отозвать доступ. Серверное бронирование пока создаёт только заявку: каталог, наличие, цены, оплата и реальные билеты не подключены. Не вводите паспортные данные.

### Настройка PostgreSQL и SMS

1. Создайте базу PostgreSQL у managed-провайдера или установите PostgreSQL 17 локально.
2. Для локального PostgreSQL задайте текущий пароль суперпользователя в переменной среды и запустите setup-скрипт. Он создаст `astana_travel`, ограниченную роль приложения, сгенерирует случайные локальные пароли и запишет их только в игнорируемый Git файл `.env.local`:

   ```powershell
   $env:POSTGRES_ADMIN_PASSWORD = "<текущий пароль PostgreSQL>"
   npm run db:setup-local
   Remove-Item Env:POSTGRES_ADMIN_PASSWORD
   ```

   Скрипт откажется перезаписывать существующий `.env.local`. Если используете managed PostgreSQL, скопируйте `.env.example` в `.env.local` и задайте URL базы вручную.
3. Примените схему:

   ```bash
   npm run db:migrate
   ```

4. Для локальной разработки оставьте `AUTH_SMS_MODE=console`; коды появятся в консоли Next.js. Этот режим запрещён вне `NODE_ENV=development`. Для реальных SMS создайте Twilio Verify Service и задайте `AUTH_SMS_MODE=twilio`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` и `TWILIO_VERIFY_SERVICE_SID`.
5. Создайте первый аккаунт через регистрацию и подтвердите номер. Затем выдайте ему права администратора:

   ```bash
   npm run admin:promote -- +77001234567
   ```

   Номер должен совпадать с подтверждённым номером зарегистрированного пользователя.
6. Для Vercel добавьте эти переменные в Environment Variables. Выполняйте миграцию отдельно в deployment workflow до переключения приложения на новую схему; не помещайте секреты в репозиторий.

В продакшене без базы приложение явно показывает, что серверная авторизация недоступна, и не переключается на демо-админку. Реальные покупки требуют отдельной интеграции поставщиков, проверки актуальной цены/наличия и платёжного провайдера.
